# 交付与归档

## 1. 交付顺序

1. Remotion / FFmpeg 产出 12Mbps 母版。
2. 用目标环境的转码工具生成约 2Mbps 的预览 mp4，拿可访问链接。
3. 在对话里发预览链接；用户确认后再归档本地。
4. 归档后核对文件大小、时长、分辨率、MD5/SHA 与母版一致。

**预览链接只用于看片，不当母版。**

## 2. 本地目录

```text
日期_脚本名/
├── versions/
│   ├── 脚本名_v1.mp4
│   ├── 脚本名_v2.mp4
│   └── 脚本名_v3.mp4
├── 脚本名_v3.mp4          # 可选：最新版副本
├── 脚本名_封面.png
├── 脚本名.srt
├── 脚本名_发布文案.txt
└── 脚本名_来源.json
```

- 文件夹名 = `日期_脚本名`，日期用当天，例如 `20261126_03_AI攻克黎曼猜想`。
- 视频文件名 = 脚本名；版本从 v1 起，顺序编号。
- **保留全部版本，不删旧版**；旧版只放 `versions/`，不要覆盖。
- 封面 3:4；首帧可烧进视频第 1 帧。

## 3. 平台交付（以飞书为例）

- 按用户指定文档、子表、单元格写入；不要自行换位置。
- 单文件 >20MB 不要直传单元格：优先给可访问链接并说明时效；必须入飞书时，分卷 zip（每卷 <20MB）或走云盘/视频消息通道。
- 不要假设 zip 一定能把视频压到 20MB 以下；长片要先算体积再选通道。12 秒 12Mbps 约 18MB，已经接近 20MB 上限；再长必超。
- 飞书 Drive 单文件上限约 20MB；超过会报 `1061043`。
- 跨租户附件不能直接把文件 token 写进单元格，会报 `all file has no relation`；走目标平台的文件/素材上传通道。
- 上传后核对单元格附件大小、文件名、可下载性。
- **没有飞书**：本地归档 + 网盘/任意可访问 mp4 链接即可，不要因为平台缺失卡住交付。

## 4. 版本与确认

- 用户确认前，不覆盖本地成片；先发 CDN 预览。
- 用户确认后，把该版本放进 `versions/`，编号递增。
- 后续改版生成 v2/v3，旧版保留；不要用“最新版覆盖”代替版本管理。
- 交付时说明：版本号、时长、分辨率、帧率、码率、文件大小、MD5。

## 5. 常见传输问题

| 现象 | 处理 |
|---|---|
| mp4 直传返回空地址 | 改 zip 传输；或走本机/视频消息通道 |
| 飞书 >20MB 上传失败 | 打 zip；仍超限则分卷或换通道 |
| 跨租户附件写入失败 | 走目标平台的文件/素材上传通道，不要直接写 token |
| 预览转码只有 1.5–2Mbps | 只当预览；母版用 Remotion + FFmpeg 12Mbps |
| 可访问链接过期 | 重新转码取新链接；不要拿过期链接交付 |
| 本地时长缓存不更新 | 先改临时名再改回，刷新文件管理器缓存 |
